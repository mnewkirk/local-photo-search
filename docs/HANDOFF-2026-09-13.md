## The immediate ask: run `match-faces` / `recluster-faces` from the replica UI

**Symptom.** On `/admin/maintenance` (replica, `localhost:8001`), the
maintenance sweep refuses those two stages with a 400.

**Why.** `photosearch/maintenance_sync.py:54` — they are in `EXCLUDED_STAGES`:

```python
EXCLUDED_STAGES = frozenset({"colors", "dedup_photos", "match_faces",
                             "recluster", "requeue"})
```

The in-code reason for these two is *"already served by export-face-state /
apply-face-state"*. That is true of the **CLI**, and false of the **UI** — which
is why it reads as a missing feature rather than a deliberate limit. The other
three exclusions are on firmer ground and should stay: `colors` needs pixels the
replica doesn't have, `dedup_photos` DELETEs, `requeue` is a no-op because the
fleet claims from the NAS.

**Why it matters right now.** The 2026-09-12 shoot has 1,020 photos with faces
detected and **1 named face**. Matching is exactly the step that is blocked, and
it gates `review-faces` too — that tool learns the team's jersey colour from
already-named faces on the date.

### The shape of the fix

The push model already has three modes (`maintenance_sync.push_mode`):

| mode | meaning | example |
|---|---|---|
| `trigger` | cheap + deterministic → ask the NAS to redo it | `geocode`, `infer` |
| `transfer` | expensive on the N100 → ship the computed rows | `stacking` |
| `excluded` | must not run here at all | `colors`, `dedup_photos` |

**Face work needs a fourth mode**, because it is the one case that is expensive
on the NAS *and* safe to compute remotely: compute on the desktop, ship a
face-state file, apply on the NAS. The CLI pair already implements exactly this
and is battle-tested (a real run moved ~230k faces):

```
photosearch recluster-faces            # desktop, hnswlib, minutes
photosearch export-face-state --out face.db     # ~9 MB
cat face.db | ssh nas 'cat > …/face.db'         # UGREEN blocks scp/rsync
photosearch apply-face-state --from face.db --apply   # on the NAS
```

`apply-face-state` is **additive by default** — it only fills faces unmatched on
the NAS — so it cannot clobber curation there. That is what makes this safe to
wire into a button.

**Suggested work:** add `FACE_STATE_STAGES = {"match_faces", "recluster"}` with
a `push_mode` of `"face_state"`, implement the export→stream→apply path in
`maintenance_sync.push_to_nas`, remove those two from `EXCLUDED_STAGES`, and let
the existing `/admin/maintenance` sweep UI drive it. Watch: the replica must be
in-sync first (the existing fingerprint pre-flight already enforces this), and
`recluster` wipes `ignored_clusters` — the remap problem is solved and worked
through in `rollback_calvin.py` / the Calvin memory note, so reuse that approach
rather than reinventing it.

## Remaining backlog, in the order I'd take it

### 1. Replica face stages (above) — the live complaint
**Built in `f209884`, not yet deployed** — see `docs/HANDOFF-2026-09-13-deploy.md`.

### 2. D4 — make silent write failure loud
`ingest-incoming` must compare files-moved vs rows-written and fail loudly on
divergence. **This is not hypothetical**: on 2026-09-12 it moved 2,040 files and
wrote **zero rows** (lock contention), discovered a day later by absence. ~20
lines. Same treatment for `index_activity`, whose newest row on the replica was
2026-08-31 — a two-week silence spanning ingests.

### 3. S2 + S4 as one schema v30 migration
- **S2 `photo_scores`** — split the volatile aesthetic scalars out of `photos`.
  SQLite rewrites whole rows, so `normalize-aesthetics` dirties ~503 MB to
  change 8 bytes/row. Split on **mutability, not topic**: the volatile scalars
  are 3.2 MB, the big `aes_*` text is 158 MB written once. Takes a normalize
  night from ~503 MB to ~7–10 MB. Also fixes `min_quality`'s unindexed 503 MB
  scan (`search.py:1844`). Costs a join on the hot filter path shared by Search,
  MCP tools and the Ask agent — wants its own tests.
- **S4 `worker_processed`** — rebuild as `WITHOUT ROWID` + FK CASCADE, purging
  228,194 orphans (18.5%). ~82 MB → ~45 MB.

Both want v30; do them together. v30 is deliberately still free — S5 dropped its
index unconditionally rather than behind a version gate.

### 4. ARW/video folder merge — 24 `*_unknown-camera` folders

Backlog is a MERGE, matched by **filename stem**, not by date — some dates have
two bodies. See the memory note for the traps.

### 5. Intra-cluster congruence review
Given one cluster scoped to a date range, are its faces one person? Complement
to the shipped label-conflict tool. `split_cluster` and
`POST /api/faces/clusters/{id}/split` already compute it — the gap is showing
the faces instead of a size histogram.

## Traps worth not rediscovering

- **`pgrep -f "<pattern>"` matches the watcher itself.** Bit three times in one
  day. See the CLAUDE.md section "Watching a long job".
- **SSE endpoints die with the browser.** A maintenance sweep launched from a
  phone was cancelled mid-run by a screen lock. Long jobs go over SSH with
  `nohup`, or detached on the NAS.
- **`match_source='manual'` is not ground truth.** Photos 242636/242637 yielded
  three wrong manual tags in one day.
- **Mirroring a label change must not rebuild face rows** (`f83f0f8`) — it
  renumbers every face on the photo and the open modal's ids go stale.
- **Tests can assert the bug.** Three of mine asserted the broken mirror
  contract and passed green while the feature was broken in the UI.
