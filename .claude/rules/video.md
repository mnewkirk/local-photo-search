# Video — traps

Full history: docs/notes/video.md (cite by heading). Backfill runbook: docs/plans/video-support.md Step 8 — backfill NOT started; do not register, run the fleet or sample until the owner asks.

- **Data model.** A video is a `photos` row with `media_type='video'`; NULL means still. Never `UPDATE` every row to set `'photo'` — it holds the NAS write lock over the whole table. Side tables: `video_meta`, `video_tracks`, `video_subjects`.
- **`db.PASS_MEDIA` says which rows each pass may claim** (`still`/`video`/`any`). Add every new pass to it: `db.media_sql` raises `KeyError` on a missing pass, and `tests/test_pass_media.py` iterates `WORKER_PASSES`. `verify` is `still` (it reads pixels); `category-content`/`keywords` are `any`.
- **Pixel readers skip videos.** Every reader that predates video (purge-nonimage, stacking, sharpness, rank_measure, upscale, split, book export, Google upload, colors, cull, `similar_by_photo(media=…)`) must skip them — use `db.is_video_row` or `db.media_filter_sql`. A new pixel reader must too.
- **The NAS never decodes or probes (owner decision D19).** The NAS walks the tree, inserts rows, stores uploads (`POST /api/videos/{id}/assets`), serves Range reads and runs Live-pairing SQL. No ffmpeg in the image. Do not move probing onto the NAS. Only exception: `unwrap-zip-videos` (stdlib `zipfile`, no decode).
- **Five worker passes.** Order lives in `batch_state.WORKER_PASSES` and its mirrors: `video-probe` → `video-proxy` → `video-scan` → … `video-subjects` → … `video-describe` before `verify`/text passes. `video-proxy` reads `proxy_needed` set at probe submit; video-describe must drain before the text passes that read its description.
- **The video passes need `--native`.** ffprobe is not in the Docker worker image. Discovery: `video_probe.find_ffprobe` (`PHOTOSEARCH_FFPROBE`, PATH, `~/.local/bin`) and `video_proxy.find_ffmpeg` (`PHOTOSEARCH_FFMPEG`, …); a pass drops itself if a tool is missing. The static ffprobe segfaults resolving `localhost` — point workers at `127.0.0.1`.
- **Strict roles, no fallback.** `video-describe` uses role `video` (`PHOTOSEARCH_LLM_VIDEO_MODEL`) with no fallback; an unset role raises `describe.RoleModelNotConfigured`. That or `ContextOverflow` raises `worker.PassHalted`: finished results are submitted, the rest released with no attempt spent. `video-subjects` (`PHOTOSEARCH_LLM_SUBJECT_MODEL`) falls back to the aesthetics model. Defaults: `rerun.FLEET_ROLE_MODELS`.
- **Unreadable is stored once, never re-decoded.** A probe verdict is a stored `probe_error`; transport errors are omitted (deferred); a tool failure is a failure row. Unreadable and Live rows count as done in batch state and are hidden from default search.
- **Most "moov atom not found" files are ZIPs, not corruption.** Probe stores `probe_error='zip_wrapped'` and does not unzip; `video-scan` unwraps inside its download. Member selection and caps live in `zip_video.py` (`select_video_member`, `ZIP_MAX_BYTES`, `ZIP_MAX_RATIO`, `ZIP_SIZE_SLACK`, `ZIP_SIZE_FLOOR`) and are shared by scan and unwrap — do not fork them. Exactly one video member; `__MACOSX/` and `._*` ignored.
- **ZIP-wrapped video unwrap (`unwrap-zip-videos`, NAS CLI).** Extract to an `O_EXCL` temp, hash while writing, fsync file + dir; `os.link` the zip to `<name>.zip` (`EEXIST` refuses, never overwrites); `os.replace` the video under the original name, so `filepath`/`folder` never change. Never delete the zip. `--apply` needs `--audit` and holds `ingest._sweep_lock`; `--undo` restores only on a size + sha256 match.
- **Dates are a per-camera-family dispatch, not one offset (D14 as built).** `video_probe.capture_date`: Apple creationdate verbatim; Android `creation_time − duration`; Sony XAVC / Kodak PIXPRO write local time with a `Z` (`_date_local_z`) — never convert it. Bump `PROBE_VERSION` only after re-validating on a larger sample.
- **Live pairing** runs server-side at probe submit (`video_probe_store.find_live_still`). Paired clips are hidden behind the still and never analysed (D3).
- **Throttle.** `?purpose=worker` reads go through a token bucket (`PHOTOSEARCH_VIDEO_STREAM_MBPS`, default 30) and a stream cap (`PHOTOSEARCH_VIDEO_WORKER_STREAMS`, default 4); over the cap is `503 Retry-After: 10`. Keep `-n 2`. Don't add an unthrottled worker read path.
- **Faces: one `faces` row per within-video identity that passes the gate** (`video_analysis.face_row_eligible`: ≥ 3 detections, or ≥ 0.5 s present with ≥ 2 — one detection at 2 fps is already a 0.5 s cell). Every identity keeps a `video_tracks` row; below the gate `face_id` is NULL, so every `video_tracks.face_id` reader must take NULL. A carried human label promotes a gated identity. `video-rescan-fragmented` (NAS, dry run default) re-queues the scan for videos scanned before the gate. The bbox is in native display px (the space of `photos.image_width/height`), not rep-frame px. All coordinate systems are documented once, in `video_scan_store`'s docstring. Crops come from the uploaded crop / rep frame, never the video; `warm_crops` skips video faces. A re-scan carries labels via `video_scan_store.match_labels`, plus `face_person_exclusions`.
- **Uploads are staged** (v38). Scan writes into a new generation dir and installs nothing; only the committed submit records `scan_generation`, bumps `poster_version` and installs posters + crops. video-subjects/-describe carry `scan_generation` and defer a result from a replaced generation — never map `face_ix` onto new tracks.
- **Subject share** is read `GROUP BY faces.person_id` at query time, so a relabel needs no recompute. Its search params sit behind `PHOTOSEARCH_VIDEO_SUBJECT_SHARE` (off): off, `/api/search` 400s on them and tool schemas omit them. The modal's subject timeline always shows.
- **Quality** (D11): shake / noise / focus / exposure are numbers only. No tag until a holdout eval gates one.
- **Playback proxies (`video-proxy`, D12).** `video_proxy.needs_proxy` is pure: proxy unless h264 + yuv420p/yuvj420p + mp4/mov/m4v + long edge ≤ 3840, read from stored `probe_json`. Output H.264 8-bit `yuv420p`, rotation baked in, HDR tone-mapped. Transcode on the desktop; `PUT /api/videos/{id}/proxy` goes to the NAS only (the replica returns 409). The UI picks via `PS.canPlayVideo` / `PS.chooseVideoSource`.
- **Deploy the NAS first**, then the workers together; run video passes `--native` only.
