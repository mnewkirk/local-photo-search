# Frontend — traps

Full history: docs/notes/frontend.md (cite by heading). Page reference: .claude/skills/photo-search/reference/frontend-pages.md.

- **No build step.** Pages are plain React UMD in `frontend/dist/`. Write `React.createElement` (pages alias it `var e = React.createElement`), never JSX. The Dockerfile bakes `frontend/` into the image (`COPY frontend/ frontend/`), so an edit reaches the NAS only after an image rebuild.
- **Frontend has no linter — `scripts/check-frontend-refs.js`.** Run `node scripts/check-frontend-refs.js` (or `cd frontend && npm run check:refs`) after every page edit. A syntax check does not catch a call to a name the page never defines: `new Function(src)` accepts it, and the page then throws `ReferenceError` only when someone clicks. The script also flags `PS.*` calls that `shared.js` never defines. CI runs it through jest and `tests/test_frontend_refs.py`.
- **Editing the checker.** Blank comments and strings in one left-to-right scan, not in layered regexes (either order invents phantom names). `shared.js` is an IIFE: only `window.PS` escapes, so never collect its inner names as globals. Doing that made the checker pass the very bug it was written to catch.
- **Shared frontend helpers go on `PS.*` in `shared.js`**, never copied between pages. Examples: `PS.parseSSEChunk`, `PS.parseSSEFrame`, `PS.poll`, `PS.PhotoModal`, `PS.SharedHeader`. A helper defined in one page and called bare from another is the `ReferenceError` above.
- **Poll with `PS.poll`, never `setInterval`.** `setInterval` fires whether or not the last request returned. On a starved NAS it filled every request thread, and the status page wedged the box it reported on. `PS.poll(fn, ms)` re-arms only after `fn`'s promise settles, pauses while the tab is hidden, and returns `stop()`, which aborts the in-flight call. `fn(signal)` must **return** its fetch chain (`Promise.all` for several); a fire-and-forget fetch defeats it. `setInterval` stays fine for a pure UI tick, such as a TTL countdown. Tests: `frontend/__tests__/poll.test.js`.
- **SSE consumers.** `EventSource` cannot POST, so read SSE with `fetch` + `response.body.getReader()` and parse frames with `PS.parseSSEFrame`/`PS.parseSSEChunk`. Cancel with `AbortController.abort()`; the server notices `request.is_disconnected()` and trips the job's `should_abort`. Act on the terminal `done` event, not on stream close: the server can hold the stream open after `done`.
- **Replica card only in replica mode.** The Replica freshness card on `/status` renders only when `/api/admin/replica-status` reports `replica_mode` (`PHOTOSEARCH_NAS_URL` set). Keep it gated so the NAS's own `/status` stays unchanged.
- **Workers panel reads the authoritative queue.** The Workers panel and fleet launcher live on `/admin/maintenance`, not `/status`. They fetch `/api/admin/workers/queue-status`, which proxies the NAS's `/api/worker/status` in replica mode. The local replica DB is a fully processed snapshot, so its own queue reads about 0. `GET /api/admin/workers/fleet-status` is process status, not queue depth.
- **On-demand pass re-runs (M28): describe drags its dependents.** In `PS.PhotoModal`, checking `describe`, `verify` or `video-describe` must also check `category-content` + `keywords`. Re-describing alone leaves them extracted from stale text.
- **Re-run writes are NAS-authoritative, then mirrored.** `POST /api/admin/rerun-passes` with `mode=sync` computes on the desktop, submits to the NAS, then mirrors through `/api/admin/mirror-photos` → NAS `GET /api/photos/{id}/mirror-fields` → `rerun._apply_mirror`. `mode=queue` calls the NAS `clear-pass`. A NAS image older than M28 404s `/mirror-fields` (`mirrored:0`); redeploy the NAS first. Single-result submits use `WorkerClient(..., probe=False)` to skip the startup connectivity probe.
- **Deploy panel: never `docker compose up` photosearch from inside its own container.** All processes in a container share one PID namespace. Recreating the container kills the compose subprocess mid-restart and strands the new container in Created state. `setsid`/`nohup` do not help. `POST /api/admin/restart` launches a detached `docker:cli` helper (`photosearch-restart-helper`) that mounts `HOST_REPO_DIR`, the **host** repo path; the in-container `/repo` means nothing to a sibling container.
- **Restart shutdown handshake.** Before launching the helper, restart sets every live `worker_claims.expires_at` to now + 15 minutes, so in-flight batches survive the gap. On shutdown, `web.py` sets `worker_api._shutting_down`, and the middleware returns `503 Retry-After: 30` on `/api/worker/*` and `/api/photos/<id>/full`. `WorkerClient._request()` sleeps and retries. `stop_grace_period: 60s` drains in-flight transfers. Keep every step when you edit restart.
- **`docker-build` passes `--build-arg GIT_SHA=$(git rev-parse HEAD)` explicitly.** Env-var expansion in the compose file sometimes resolved to "unknown". `/api/admin/version` compares `/app/BUILD_SHA` with HEAD. Git calls need `-c safe.directory=*` (UGOS owns the repo as another uid).
- **`REPO_DIR` empty-string trap.** In a manual recovery, run `unset REPO_DIR` before `docker compose up`. `${REPO_DIR:-...}` falls back only when the variable is unset; set-but-empty drops the `/repo` mount and breaks the deploy panel on the next boot.
